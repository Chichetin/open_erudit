# План реализации open_erudit

Документ для агента-исполнителя. Задачи идут строго по порядку: каждая опирается
на предыдущую. Внутри задачи — что сделать, где, и по каким признакам считать
её законченной. Каждая задача заканчивается коммитом в `main` (см. `CLAUDE.md`).

Архитектурные решения и их обоснование — в `PLAN.md`. Здесь их не пересматриваем.

---

## Инварианты

Нарушение любого из них — ошибка, даже если тесты зелёные.

1. **Сервер — единственный арбитр.** Всё, что приходит от клиента, проверяется
   заново: очередь хода, наличие фишек на стойке, геометрия, словарь, очки.
2. **Игрок не видит чужую стойку и содержимое мешка.** Единственное место, где
   состояние превращается в то, что уходит в сокет, — `projection.for_player()`.
   Никакой другой код не сериализует `Game` для отправки.
3. **`erudit/` ничего не знает про HTTP.** Ни импортов FastAPI, ни `await` ради
   сети, ни глобального состояния.
4. **Мешок перемешивается только через переданный `random.Random`.** Никаких
   обращений к глобальному `random` — иначе партии невоспроизводимы в тестах.
5. **Все координаты — `(row, col)`, 0-индексные,** от левого верхнего угла.
   Центр доски — `(7, 7)`.

## T1. Конфигурация набора

**Файлы:** `erudit/config.py`. Данные уже лежат в `data/tilesets/scrabble_ru.json`
(сверено, сумма ровно 104 фишки: 102 буквенных + 2 пустышки).

```python
@dataclass(frozen=True)
class TileSpec:
    letter: str
    value: int
    count: int

@dataclass(frozen=True)
class TileSet:
    id: str
    name: str
    board_size: int          # 15
    rack_size: int           # 7
    bingo_bonus: int         # 0 — бонус за все 7 фишек выключен
    center: tuple[int, int]  # (7, 7)
    board: list[str]         # 15 строк по 15 символов
    tiles: list[TileSpec]

def load_tileset(path: Path) -> TileSet: ...
```

Символы раскладки: `T`=утроение слова, `D`=удвоение слова, `t`=утроение буквы,

**Критерии приёмки:** тест проверяет, что сумма `count` плюс `blank_count` равна
104; что все 15 строк раскладки имеют длину 15; что бонусов ровно 8×`T`, 16×`D`
плюс центр, 12×`t`, 24×`d`; что раскладка симметрична относительно центра.

**Коммит:** `данные: добавить конфиг русского набора Scrabble и его загрузку`

## T3. Доска и геометрия хода

**Файлы:** `erudit/board.py`, `erudit/rules.py`, `tests/test_rules.py`.

```python
@dataclass(frozen=True)
class PlacedTile:
    tile_id: int
    letter: str      # у пустышки — назначенная игроком буква
    is_blank: bool
    player_id: str
    move_no: int

@dataclass(frozen=True)
class Placement:
    row: int
    col: int
    tile_id: int
    letter: str      # для пустышки — выбранная буква

class MoveError(Exception):
    """Ход отклонён. Текст сообщения показывается игроку, поэтому — по-русски."""
```

### Правила геометрии (`validate_geometry`)

Проверяются строго в этом порядке, первая же нарушенная — `MoveError`:

1. Список размещений не пуст.
2. Все координаты в пределах доски и попарно различны.
3. Все целевые клетки свободны.
4. Все новые фишки лежат в одной строке **или** в одном столбце.
5. Вдоль этой линии между крайними новыми фишками нет пустых клеток — разрывы
   допустимы только там, где уже стоят старые фишки.
6. Если доска пуста — одна из новых фишек обязана накрыть центр `(7, 7)`.
   Иначе — хотя бы одна новая фишка обязана касаться (по вертикали или
   горизонтали) уже стоящей.

Отдельный случай: **одна фишка**. Направление неоднозначно, поэтому его выбирают
по факту — берётся то направление, в котором образуется слово длиной ≥ 2.
Если слово образуется в обоих — оба идут в подсчёт.

### Сбор слов (`collect_words`)

Возвращает список слов; слово — это последовательность клеток с пометкой, какие
из них новые.

- Главное слово: непрерывная линия вдоль направления хода, включая захваченные
  по краям старые фишки.
- Для каждой новой фишки — перпендикулярное слово, если оно длиной ≥ 2.
- Последовательности длиной 1 словами не считаются и в подсчёт не идут.
- Одно и то же слово не попадает в результат дважды.

**Критерии приёмки (тесты обязательны на каждый пункт):** первый ход мимо центра
отклоняется; ход, не касающийся существующих фишек, отклоняется; ход «лесенкой»
отклоняется; ход с разрывом отклоняется, а такой же ход, где разрыв закрыт старой
фишкой, принимается; одна фишка, достраивающая слово по вертикали, принимается и
даёт одно слово; одна фишка на пересечении даёт два слова; ход, продлевающий
слово с обеих сторон, собирает его целиком.

**Коммит:** `движок: реализовать доску и проверку геометрии хода`

## T4. Подсчёт очков

**Файлы:** `erudit/scoring.py`, `tests/test_scoring.py`.

```python
def score_move(board, placements, words, tileset) -> tuple[int, list[tuple[str, int]]]
    # (сумма за ход, [(слово, очки за него), ...])
```

Правила, каждое из которых — отдельный тест:

1. Очки слова = сумма номиналов его букв с учётом буквенных множителей, затем
   всё умножается на словесные множители.
2. Бонус клетки действует **только в тот ход, когда клетка закрывается**. При
   подсчёте перпендикулярных слов бонус той же новой клетки применяется снова —
   это правильно и так и должно быть.
3. Несколько словесных множителей в одном слове перемножаются (две клетки `D` → ×4).
4. Пустышка приносит 0 очков независимо от назначенной буквы. Буквенный множитель
   на ней ничего не меняет, словесный — работает.
5. Итог хода — сумма по всем образованным словам.
6. Если `bingo_bonus > 0` и выложены все `rack_size` фишек — прибавляется сверху,
   после всех множителей. Сейчас в конфиге 0, но код и тест должны быть.

**Контрольный пример для теста** (посчитан вручную, зашить как эталон): на пустой
доске горизонтально в строке 7, столбцы 7–10 выложено `ДОМА`.
Клетка (7,7) — центр (×2 слову), (7,8)…(7,10) — обычные.
Д=2, О=1, М=2, А=1 → сумма 6, слово ×2 → **12 очков**.

**Коммит:** `движок: реализовать подсчёт очков с бонусными клетками`

## T5. Партия целиком

**Файлы:** `erudit/game.py`, `tests/test_game_flow.py`.

```python
@dataclass
class Player:
    id: str
    name: str
    token: str
    rack: list[Tile]
    score: int
    connected: bool

class Game:
    id: str
    status: Literal["waiting", "active", "finished"]
    current: int
    pass_streak: int
    move_no: int
    log: list[dict]

    def add_player(self, name: str) -> Player: ...
    def start(self) -> None: ...
    def play(self, player_id: str, placements: list[Placement]) -> MoveResult: ...
    def do_pass(self, player_id: str) -> None: ...
    def exchange(self, player_id: str, tile_ids: list[int]) -> None: ...
    def preview(self, player_id: str, placements: list[Placement]) -> Preview: ...
```

Проверки в `play` (все — на сервере, все — до изменения состояния):

- партия в статусе `active`;
- ходит тот, чья очередь (`player_id` совпадает с текущим);
- все `tile_id` действительно лежат на стойке этого игрока;
- геометрия (T3);
- каждое образованное слово есть в словаре — иначе `MoveError` со списком
  неизвестных слов, чтобы клиент мог предложить «добавить в словарь».

Только после всех проверок: фишки ставятся на доску, снимаются со стойки,
начисляются очки, добирается из мешка до 7, `pass_streak = 0`, ход переходит
дальше, в журнал пишется запись.

`preview` — то же самое, но **без изменения состояния**: возвращает
`(валидно, слова с очками, сумма, ошибка, неизвестные слова)`.

`exchange`: разрешён, только если в мешке не меньше `rack_size` фишек. Сданные
фишки возвращаются в мешок **после** взятия новых, иначе игрок может вытянуть
свои же. Ход теряется, `pass_streak += 1`.

### Конец партии

Наступает по одному из двух условий:

- мешок пуст и у кого-то опустела стойка — этот игрок получает сумму номиналов
  фишек, оставшихся у соперников, а каждый соперник теряет сумму своих;
- `pass_streak >= 6` (подряд шесть безрезультатных ходов — пасов и обменов) —
  каждый просто теряет сумму своих остатков.

**Критерии приёмки:** ход не в свою очередь отклоняется; ход фишками, которых нет
на стойке, отклоняется; отклонённый ход не меняет ни доску, ни стойку, ни счёт
(проверять сравнением снимка состояния до и после); неизвестное слово даёт ошибку
со списком слов; после хода стойка добирается до 7, пока мешок не пуст; обмен при
почти пустом мешке отклоняется; партия из шести пасов заканчивается; финальный
подсчёт остатков верен; полный прогон партии двумя игроками доходит до `finished`.

**Коммит:** `движок: собрать партию — ходы, пас, обмен, конец игры`

## T6. Словарь

**Файлы:** `scripts/build_dictionary.py`, `erudit/dictionary.py`,
`data/dictionary/overrides.json`, `tests/test_dictionary.py`.

### Скрипт генерации (запускается один раз, вручную)

```bash
uv run --group tools python scripts/build_dictionary.py
```

API проверен на живом запуске: `MorphAnalyzer().dictionary.iter_known_words()`
отдаёт кортежи `(слово, OpencorporaTag, нормальная_форма, para_id, idx)`.

Фильтр: в граммемах есть `NOUN`, `sing`, `nomn`; нет ни одной из
`{Name, Surn, Patr, Geox, Orgn, Trad, Abbr, Init}`; в слове нет дефиса; длина ≥ 2;
все символы — русские буквы. Слова приводятся к верхнему регистру и
дедуплицируются. **Ожидаемый результат — около 68 тысяч слов** (проверено:
68 140 до отсева коротких и дефисных). Если получилось радикально другое число —
не коммитить, а разобраться.

Результат: `data/dictionary/nouns.txt`, по слову в строке, отсортировано.
Файл коммитится в репозиторий.

### Модуль словаря

```python
class Dictionary:
    def __init__(self, base: set[str], overrides_path: Path) -> None: ...
    def __contains__(self, word: str) -> bool: ...
    def add(self, word: str, player_id: str) -> None: ...   # в allowed + на диск
    def ban(self, word: str, player_id: str) -> None: ...   # в banned + на диск
```

Правило: `word in allowed or (word in base and word not in banned)`.
Регистр нормализуется на входе. `overrides.json` — `{"allowed": [], "banned": []}`,
переписывается атомарно (временный файл рядом + `os.replace`).

**Критерии приёмки:** тесты работают на маленьком поддельном базовом наборе, не
читая настоящий `nouns.txt`; добавленное слово проходит проверку и переживает
пересоздание объекта; забаненное перестаёт проходить; регистр не влияет.

**Коммиты:** два — `словарь: добавить скрипт генерации из pymorphy3` и
`словарь: реализовать проверку слов с правками на лету`.
Сгенерированный `nouns.txt` — третьим: `данные: добавить словарь существительных`.

## T7. Сервер

**Файлы:** `app/main.py`, `app/sessions.py`, `erudit/projection.py`,
`erudit/storage.py`, `tests/test_ws.py`.

### Маршруты

| Маршрут | Назначение |
|---|---|
| `GET /` | лобби: кнопка «Создать партию» |
| `POST /games` | создаёт партию, возвращает `{game_id, links: [url1, url2]}` |
| `GET /g/{game_id}` | HTML игры (токен сервер не видит — он в hash) |
| `WS /g/{game_id}/ws` | игровой канал |

Ссылка игрока: `{base_url}/g/{game_id}#{token}`. Токен — `secrets.token_urlsafe(24)`,
сверка через `secrets.compare_digest`. `game_id` валидируется регулярным
выражением `^[a-z0-9]{8,16}$` **до** любого обращения к файловой системе.

### Протокол

Клиент → сервер: `hello {token}`, `draft {placements}`, `commit {placements}`,
`exchange {tile_ids}`, `pass`, `allow_word {word}`.

Сервер → клиент: `state {...}`, `preview {...}`, `presence {...}`,
`error {message}`. Журнал едет внутри `state`, отдельного сообщения на запись
в него нет — см. раздел 4 в `PLAN.md`.

Первое сообщение в сокете обязано быть `hello`. До успешной авторизации любое
другое — закрытие соединения. После каждого события, меняющего партию, всем
подключённым уходит свежий `state` — **полный персональный снапшот**, без дельт.

`commit` несёт полный список размещений: серверный черновик из `draft` для
принятия хода не используется вообще, он существует только ради `preview`.

### Проекция

```python
def for_player(game: Game, player_id: str) -> dict
```

Своя стойка — списком фишек. Чужая — только количеством. Мешок — только
количеством. Токены не попадают в проекцию никогда.

### Снапшоты

```python
def save(game: Game, dir: Path) -> None      # атомарно: tmp + os.replace
def load_all(dir: Path) -> dict[str, Game]   # при старте сервера
```

Сохраняем после каждого события, меняющего партию. Партии в статусе `finished`
старше семи дней удаляются при старте.

**Критерии приёмки (интеграционные тесты через `TestClient` с двумя сокетами):**
подключение без `hello` закрывается; чужой токен отклоняется; в `state` первого
игрока нет фишек второго и нет ни одного токена; ход не в свою очередь даёт
`error`, а не меняет состояние; после хода оба клиента получают новый `state`;
разрыв и повторное подключение с тем же токеном возвращают ту же партию с тем же
счётом; после перезапуска (пересоздание приложения из той же папки снапшотов)
партия восстанавливается.

**Коммиты:** по одному на связную часть — `сервер: создание партии и выдача
персональных ссылок`, `сервер: игровой WebSocket и проекция состояния`,
`сервер: снапшоты партий на диск и восстановление при старте`.

## T8. Клиент, базовый

**Файлы:** `app/templates/lobby.html`, `app/templates/game.html`,
`app/static/style.css`, `app/static/js/{ws,state,board,rack,draft,placement,ui}.js`.

Ванильные ES-модули, без сборки и без npm. Целевое устройство — десктоп от 1024 px.

- `ws.js` — соединение, автопереподключение с нарастающей паузой, `hello` при
  каждом открытии.
- `state.js` — хранит последний `state`, оповещает подписчиков.
- `board.js` — доска на CSS Grid, 15×15, клетка ~40 px, `data-row`/`data-col`,
  раскраска бонусов, подсветка фишек последнего хода.
- `rack.js` — стойка, выбор фишки.
- `draft.js` — черновик хода: положить, снять, очистить. Единственный источник
  правды для интерфейса о незавершённом ходе.
- `placement.js` — быстрая проверка геометрии для подсветки. **Копия правил из
  T3, и это осознанное дублирование.** Комментарий в шапке файла обязан
  указывать на `erudit/rules.py` как на источник истины.
- `ui.js` — счёт, чей ход, журнал, статус соперника, кнопки, диалог выбора буквы
  для пустышки, экран конца партии.

Порядок действий игрока: выбрал фишку → ткнул в клетку → фишка в черновике →
клиент шлёт `draft` → сервер отвечает `preview` → показывается «ЗАМОК, 24» или
причина отказа → «Подтвердить» шлёт `commit`.

Если `commit` отклонён из-за неизвестного слова, в сообщении появляется кнопка
«Добавить в словарь» — она шлёт `allow_word` и повторяет `commit`.

**Критерии приёмки:** проверяется вручную в двух окнах браузера — партия
играется от создания до конца, включая пустышку, обмен и пас.

**Коммиты:** по экранам и модулям, не одной кучей: `клиент: доска и стойка`,
`клиент: черновик хода и предпросмотр`, `клиент: журнал, счёт и статус соперника`,
`клиент: пустышки, обмен и пас`, `клиент: экран конца партии`.

## T10. Запуск

**Файлы:** `run.sh`, раздел «Запуск» в `README.md`.

```bash
./run.sh              # только LAN: uvicorn на 0.0.0.0:8000
./run.sh --tunnel     # плюс cloudflared, публичный https-адрес
```

С флагом `--tunnel`: запустить `cloudflared tunnel --url http://localhost:8000`,
выцепить из его вывода адрес `*.trycloudflare.com`, дождаться готовности и
напечатать базовый URL, по которому создавать партию. При завершении скрипта —
убить оба процесса.

Установка туннеля: `sudo pacman -S cloudflared` (пакет есть в `extra`) —
**сделано**, версия 2026.5.2.

**Важно про эту машину:** на ноутбуке поднят полнотуннельный VPN с policy-routing,
поэтому проброс порта с роутера работать не будет — ответные пакеты уходят в
туннель. В LAN всё работает без настройки: `INPUT policy accept`.

Ожидание, что Cloudflare Tunnel этой проблемы не имеет, потому что соединение
исходящее, **не подтвердилось**: Happ не пропускает порт 7844, на котором
cloudflared держит канал до Cloudflare. Подробности и что именно проверено —
в разделе 8 `PLAN.md`. С этой машины туннель работает только при выключенном
Happ.

**Коммиты:** `инфра: скрипт запуска с опциональным туннелем Cloudflare` и
`инфра: чинить определение адреса туннеля и проверять, что он встал` — второй
по итогам живой проверки: скрипт печатал `api.trycloudflare.com` вместо
выданного адреса и не замечал, что туннель не встал.

## T11. Обкатка

Сыграть полную партию с реальным соперником через туннель. Проверить: длинную
паузу между ходами (не рвётся ли сокет), закрытие и открытие вкладки, засыпание
ноутбука на стороне сервера, добавление слова в словарь по ходу партии.

Найденные проблемы — отдельными коммитами с префиксом `клиент:`/`сервер:`.

**Состояние:** до партии через туннель дело не дошло — он разваливается из-за
Happ (см. T10). По локальной сети всё проверено в браузере: доска, стойка,
черновик с предпросмотром очков, отказ по словарю с кнопкой «Добавить в
словарь» и повтором хода. Осталось именно то, ради чего задача и заведена:
длинная партия с живым соперником и поведение сокета на долгих паузах.

## Порядок и почему он такой

Движок с тестами (T1–T5) идёт раньше сервера намеренно: ошибка в подсчёте очков
самая дорогая из возможных — её замечают через несколько партий, и к тому моменту
непонятно, что именно считалось неправильно. Сервер и клиент после готового
движка — работа без сюрпризов.

Словарь (T6) стоит после движка, потому что `Game.play` уже должен уметь спросить
«есть такое слово?» — но до сервера, потому что без словаря партию не сыграть.
