# Правила работы в репозитории open_erudit

Веб-«Эрудит» на двоих. Архитектурные решения — в `PLAN.md`,
пошаговый план реализации — в `docs/IMPLEMENTATION_PLAN.md`.
Эти три файла читаются перед началом работы.

## Политика Git

**Работаем напрямую в `main`. Веток и pull request'ов нет.**
Remote: `https://github.com/Chichetin/open_erudit.git`, `gh` уже авторизован.

### Когда коммитить

Каждое **функциональное изменение** — отдельный коммит, сразу после того как оно
готово и проверено. Не копить изменения, не сваливать несколько задач в один коммит.

Функциональным изменением считается:

- новый модуль движка или новая игровая механика;
- новый HTTP-маршрут, тип WebSocket-сообщения или поле в протоколе;
- новый экран или элемент интерфейса;
- исправление бага;
- изменение данных, влияющих на игру (набор фишек, словарь, конфиг);
- новые тесты к существующему коду.

Рефакторинг без изменения поведения коммитится **отдельно** от функциональных
правок, чтобы диффы читались.

### Обязательная последовательность

```bash
uv run pytest            # обязательно зелёный
git add <конкретные файлы>   # не "git add ." вслепую
git commit -m "..."
git push origin main
```

Правила без исключений:

1. **Не коммитить со сломанными тестами.** Красный `pytest` — сначала чинится.
2. **Не коммитить нерабочий код** «чтобы не потерять». Незаконченное остаётся
   в рабочей копии.
3. **Пушить сразу после коммита.** Локальная история, не доехавшая до GitHub,
   не считается сделанной работой.
4. **Добавлять файлы поимённо.** `git add .` затянет мусор из `.idea/` и `data/games/`.
5. **Никаких токенов, ключей и снапшотов партий в истории.** Если такое попало в
   коммит — не «удалить следующим коммитом», а остановиться и сказать пользователю.

### Формат сообщения

Первая строка — на русском, повелительное наклонение, до 72 символов, с префиксом
области. Тело (если нужно) объясняет **зачем**, а не пересказывает диff.

Префиксы: `движок:`, `словарь:`, `сервер:`, `клиент:`, `данные:`, `тесты:`,
`инфра:`, `доки:`.

```
движок: посчитать очки за перпендикулярные слова

Бонус клетки применяется только в ход, когда клетка закрыта, поэтому
множители считаются по списку новых фишек, а не по всей доске.

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```

Каждый коммит завершается трейлером:

```
Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```

### Что не попадает в репозиторий

`.idea/`, `.venv/`, `__pycache__/`, `data/games/*.json` (снапшоты партий),
`data/dictionary/nouns.txt` **коммитится** (это входные данные игры, ~700 КБ).

## Технические правила

- **Python 3.13.** Не 3.14: pymorphy3 туда не ставится. Зафиксировано в `pyproject.toml`.
- **Менеджер — `uv`.** Команды: `uv sync`, `uv run pytest`, `uv run uvicorn ...`.
- **`erudit/` не импортирует `app/`.** Движок обязан работать и тестироваться без
  FastAPI. Нарушение этой границы — повод переписать, а не обойти.
- **pymorphy3 — только в `scripts/`**, в зависимости сервера не входит
  (dependency-group `tools`).
- **Сервер — единственный арбитр.** Любая проверка, продублированная в JS,
  существует только ради подсветки в интерфейсе. Ход, принятый клиентом, но
  отклонённый сервером, — это отклонённый ход.
- **Интерфейс на русском.** Сообщения об ошибках игроку — тоже.
- **Комментарии — только там, где код неочевиден.** Правила Scrabble контринтуитивны
  (бонус применяется один раз, пустышка даёт 0 очков, но множитель слова на ней
  работает) — вот это стоит пояснять.

## Проверка перед коммитом

```bash
uv run pytest -q
```

Тесты движка обязаны проходить без сети, без сервера и без словаря на диске
(словарь в тестах подменяется маленьким набором слов).
