# open_erudit — план разработки

Веб-«Эрудит» на двоих: сервер живёт на ноутбуке, игроки подключаются из браузеров,
в том числе снаружи — через быстрый туннель Cloudflare.

## 1. Принятые решения

| Решение | Выбор |
|---|---|
| Правила | Классический «Эрудит»: 15×15, проверка всех образованных слов по словарю |
| Гибкость правил | Набор фишек, доска, номиналы, бонусы — данные в JSON, не код |
| Игроки | Модель на N игроков (список + индекс текущего), UI и лобби — на двоих |
| Набор | Русский Scrabble: 104 фишки, 2 пустышки, классическая раскладка бонусов |
| Механики MVP | Джокеры-пустышки, обмен фишек, пас, конец партии. Без «бинго» +50, без таймера |
| Словарь | Существительные им. п. ед. ч. из OpenCorpora/pymorphy3 + правки на лету |
| Правка словаря | Свободный режим: любой игрок добавляет слово без подтверждения, всё пишется в журнал |
| Доступ | LAN при разработке, `cloudflared tunnel --url` для игры с удалённым соперником |
| Вход | Персональная ссылка `/g/{game_id}#{token}`, токен в localStorage |
| Стек | FastAPI + uvicorn[standard] + Jinja2, uv, Python 3.13, pytest + pytest-asyncio |
| Фронтенд | Ванильные ES-модули, CSS Grid, без сборки |
| Ввод | Тап «фишка → клетка» плюс drag & drop, оба пишут в один черновик |
| Предпросмотр | Геометрия дублируется в JS для подсветки, очки и словарь — только с сервера |
| Целевое устройство | MVP — десктоп от 1024 px; планшет следом; телефон отложен |
| Хранение | Состояние в памяти + снапшот партии в JSON после каждого хода |
| Тесты | Юнит-тесты движка + интеграционные через два WebSocket-клиента |
| Запуск | `./run.sh [--tunnel]`, печатает готовые ссылки обоим игрокам |

Python закреплён на **3.13**, потому что pymorphy3 пока не ставится на 3.14
(проверено: `uv` сам откатился на 3.13.5).

## 2. Структура репозитория

```
pyproject.toml            uv, python = "3.13"
run.sh                    uvicorn [+ cloudflared], печать ссылок
data/
  tilesets/scrabble_ru.json     доска, бонусы, фишки, номиналы
  dictionary/nouns.txt          сгенерированная база (~90–100 тыс. слов)
  dictionary/overrides.json     allow/deny, правится по ходу игры
  games/<game_id>.json          снапшоты партий
scripts/
  build_dictionary.py           офлайн-генерация nouns.txt (разовый запуск)
erudit/                   чистый движок, ничего не знает про HTTP
  config.py    загрузка набора и путей
  tiles.py     фишка, мешок, перемешивание, раздача
  board.py     доска, бонусные клетки, соседство
  rules.py     валидация размещения, сбор образованных слов
  scoring.py   подсчёт очков хода
  dictionary.py база + overrides, add_word/ban_word
  game.py      Game: place/pass/exchange, смена хода, конец партии
  projection.py персональный вид состояния (своя стойка видна, чужая — нет)
  storage.py   сохранение и восстановление снапшота
app/
  main.py      маршруты и WebSocket
  sessions.py  реестр партий, выдача и проверка токенов
  templates/   lobby.html, game.html
  static/      board.js, rack.js, draft.js, placement.js, ws.js, state.js, style.css
tests/
  test_scoring.py test_rules.py test_game_flow.py test_dictionary.py test_ws.py
```

Ключевой принцип: `erudit/` не импортирует ничего из `app/`. Движок тестируется
без сервера, сервер — тонкая обёртка над ним.

## 3. Модель состояния

```python
Tile      = (id, letter | None, value)          # letter=None у пустышки
Cell      = None | (tile_id, letter, is_blank, player_id, move_no)
Player    = (id, name, token, rack: list[Tile], score, connected)
Game      = (id, tileset_id, board: 15×15, bag: list[Tile], players: list[Player],
             current: int, pass_streak: int, move_no: int, log: list[Event], status)
```

`status`: `waiting` → `active` → `finished`.
Конец партии: мешок пуст и кто-то выложил всю стойку, либо шесть пасов подряд.
В конце у каждого вычитается сумма оставшихся фишек; вышедший первым получает
сумму чужих остатков.

**Проекция.** Клиенту уходит не `Game`, а результат `projection.for_player()`:
своя стойка целиком, чужая — только количество фишек, мешок — только количество.
Это единственное место, где решается, что игрок имеет право видеть, поэтому
приватность стойки проверяется одним тестом на эту функцию, а не по всему коду.

## 4. Протокол WebSocket

Состояние партии — единицы килобайт, поэтому никаких дельт: после каждого
события сервер шлёт **полный персональный снапшот**. Это убирает целый класс
ошибок рассинхронизации ценой лишнего трафика, которого на двоих не жалко.

Клиент → сервер:

| Сообщение | Смысл |
|---|---|
| `hello {token}` | первое сообщение после подключения, авторизация |
| `draft {placements}` | черновик изменился, посчитай предпросмотр |
| `commit {placements}` | подтвердить ход (список кладётся заново — сервер не доверяет своему черновику) |
| `exchange {tile_ids}` | обменять фишки, ход теряется |
| `pass` | пас |
| `allow_word {word}` | добавить слово в словарь |

Сервер → клиент:

| Сообщение | Смысл |
|---|---|
| `state {...}` | полный персональный снапшот |
| `preview {valid, words, total, error}` | результат проверки черновика |
| `presence {players}` | кто онлайн, чей ход |
| `log {entry}` | строка в журнал |
| `error {message}` | отказ с причиной |

Переподключение: клиент открывает сокет, шлёт `hello`, получает `state` — и
продолжает с того же места. Отдельной логики восстановления не нужно.

## 5. Словарь

1. `scripts/build_dictionary.py` перебирает словарь pymorphy3 через
   `dictionary.iter_known_words()` и оставляет слова с тегами `NOUN + sing + nomn`,
   отбрасывая `Name`, `Surn`, `Geox`, `Abbr` и прочие. Проверено на живых
   примерах: `кот` проходит, `бежать`, `красный`, `коты`, `Москва` — нет.
   На выходе получается **68 140 слов**.
2. Результат — обычный текстовый файл, коммитится в репозиторий. На сервере это
   `set[str]` в памяти: десятки тысяч коротких строк, единицы мегабайт.
3. `overrides.json` (`allowed` / `banned`) читается при старте и переписывается
   при каждой правке. Проверка: `word in allowed or (word in base and word not in banned)`.
4. pymorphy3 нужен **только** этому скрипту и в зависимости сервера не входит.

## 6. Безопасность на публичном адресе

Игра будет доступна из интернета, поэтому минимум обязателен:

- Токен — `secrets.token_urlsafe(24)`, сверка через `secrets.compare_digest`.
- Токен передаётся в hash-части ссылки (`#token`) — браузер не отправляет её на
  сервер, значит токены не попадут ни в логи uvicorn, ни в логи Cloudflare.
- Ход принимается только от игрока, чья очередь; проверка на сервере, всегда.
- `game_id` валидируется регулярным выражением до любого обращения к файлу —
  снапшоты лежат на диске, и путь не должен собираться из пользовательского ввода.
- Ограничение размера сообщения и числа одновременных партий, TTL для старых.

## 7. Этапы

**Э0. Каркас.** `uv init`, зависимости, пустой FastAPI, `pyproject` на 3.13.
Сверить и записать `scrabble_ru.json` — распределение 104 фишек, номиналы,
раскладка бонусных клеток.

**Э1. Движок и тесты.** `tiles`, `board`, `rules`, `scoring`, `game`.
Тесты сразу на неприятные места: пересекающиеся слова считаются все;
бонус клетки применяется один раз и только в ход, когда клетка закрыта;
джокер даёт 0 очков, но участвует в словах; первый ход обязан накрыть центр;
пас-стрик и финальный подсчёт остатков.

**Э2. Словарь.** Скрипт генерации, `dictionary.py`, overrides, тесты.

**Э3. Сервер.** Реестр партий, токены, создание игры, WebSocket, проекция,
снапшоты на диск и восстановление при старте. Интеграционные тесты на двух
клиентах: очередь ходов, приватность стойки, переподключение.

**Э4. Клиент, базовый.** Доска на CSS Grid, стойка, тап-ввод, черновик,
предпросмотр очков, кнопки «Подтвердить / Сбросить / Пас / Обмен», диалог
выбора буквы для пустышки.

**Э5. Клиент, доводка.** Drag & drop поверх того же черновика, журнал ходов,
статус соперника, подсветка последнего хода, экран конца партии.

**Э6. Запуск.** `run.sh`: uvicorn, при `--tunnel` — cloudflared, выдёргивание
адреса `trycloudflare.com` из его вывода, печать двух готовых ссылок.

**Э7. Обкатка.** Партия целиком с реальным соперником, правка мелочей.

Порядок не случаен: движок с тестами закрывает самую дорогую ошибку
(неправильный подсчёт очков замечают через несколько партий), а сервер и клиент
после него — работа без сюрпризов.

## 8. Что было неизвестно и чем закончилось

- **Раскладка набора — выяснена и зафиксирована** в `data/tilesets/scrabble_ru.json`.
  Сумма сходится точно: 102 буквенных фишки плюс 2 пустышки = 104. Раскладка
  бонусов — классическая доска Scrabble (8 клеток утроения слова, 16 удвоения
  плюс центр, 12 утроения буквы, 24 удвоения буквы).
- **API перебора словаря pymorphy3 — проверен на запуске.**
  `MorphAnalyzer().dictionary.iter_known_words()` отдаёт кортежи
  `(слово, тег, нормальная форма, para_id, idx)`; фильтр по
  `NOUN + sing + nomn` за вычетом имён, топонимов и аббревиатур даёт
  **68 140 слов**.
- **Поведение быстрого туннеля с WebSocket на длинной партии** — единственное,
  что осталось проверить живой игрой (задача T11).

Пошаговый план реализации — в `docs/IMPLEMENTATION_PLAN.md`,
правила работы с репозиторием — в `CLAUDE.md`.
